# Penguin Patcher Architecture

## Overview

Penguin Patcher creates a single USB drive that can boot Linux on Apple Silicon
Macs. It combines:

1. A **macOS installer** that runs on the target Mac and installs a small
   `m1n1` Stage 1 stub on the internal SSD.
2. A **USB image** with a macOS-readable installer partition and a bootable
   ARM64 EFI partition containing Linux.

## Components

### 1. USB Maker (`usb-maker/`)

Builds a `.iso` or raw disk image with two partitions:

| Partition | Filesystem | Contents |
|---|---|---|
| `PENGUIN` | APFS or HFS+ | `Penguin Patcher.app`, README, release notes |
| `EFI` | FAT32 (ESP) | `m1n1` Stage 2, U-Boot, GRUB, kernel, initrd, squashfs rootfs |

Build steps:

1. Download/patch Asahi kernel + modules for target distro.
2. Create initrd and squashfs live rootfs.
3. Build `m1n1` Stage 2 binary (`m1n1.bin` + DTBs + `u-boot-nodtb.bin.gz`).
4. Create disk image with both partitions.
5. Copy `Penguin Patcher.app` to the macOS partition.

### 2. macOS Installer (`installer/`)

A Swift or Objective-C app with a Python/AppleScript helper that:

1. Detects the Apple Silicon machine model.
2. Verifies the USB ESP contains the correct `m1n1` Stage 2 for that model.
3. Shrinks the internal APFS container by ~3GB.
4. Creates a new APFS container labeled `penguin-stub`.
5. Installs `m1n1` Stage 1 stub into that container.
   - This requires machine-specific keys generated by Apple's boot firmware.
   - We reuse the logic from Asahi Linux's installer.
6. Blesses the stub so it appears in the boot picker.
7. Optionally copies the Linux kernel/initrd from USB to internal disk for
   disk-only boot (future feature).

### 3. Kernel Builder (`kernel-builder/`)

- Clone Asahi Linux kernel source.
- Apply distro-specific config (Fedora/Ubuntu/Debian).
- Build kernel image, DTBs, and modules.
- Package modules and firmware for the initrd/squashfs.

### 4. Device Profiles

Apple Silicon devices differ in:
- SoC (M1, M1 Pro/Max/Ultra, M2, M3, M4)
- Number of CPU cores
- GPU cores
- Display/HDMI/Thunderbolt controllers
- WiFi/Bluetooth chipset

Each device needs the right Device Tree and firmware. Asahi Linux already maps
these. We maintain a lookup table from machine model ID to DTB/firmware set.

## Boot Flow

1. User reboots Mac, holds power button.
2. Apple boot picker shows `penguin-patcher` entry (from internal stub).
3. iBoot2 loads `m1n1` Stage 1 from the internal APFS stub.
4. `m1n1` Stage 1 locates `m1n1` Stage 2 on the USB ESP (`/m1n1/boot.bin`).
5. `m1n1` Stage 2 contains U-Boot, which presents a UEFI environment.
6. U-Boot loads GRUB from `/EFI/BOOT/BOOTAA64.EFI`.
7. GRUB loads kernel and initrd from USB.
8. Linux boots into live environment.

## Reversibility

- The `penguin-stub` APFS container is independent.
- Boot into macOS Recovery, open Disk Utility, delete `penguin-stub`.
- Mac returns to stock boot configuration.

## Open Questions

1. Can `m1n1` Stage 1 reliably find Stage 2 on an external USB after install?
2. How do we handle macOS updates that might affect the stub container?
3. Gatekeeper / notarization for the macOS installer app.
4. Can we make the stub smaller than 2.5GB?
5. Should we support both live USB and install-to-internal options?
